# 独立分析与交叉检查

围绕用户需要的结果组织工作：明确任务与材料，独立分析，检查会改变结论的矛盾或缺口，形成判断及下一步。分析单位是具体问题与证据，不为展示多个声音增加工作。

## 参考文件

- 执行前读取 [设计原则](references/design-principles.md)。
- 分配独立任务或开展复核时读取 [分析协议](references/analysis-protocol.md)。
- 需要补充分析角度时读取 [分析视角](references/analysis-lenses.md)，不必全部使用。
- 使用 Subagent 时，按宿主读取 [Codex 适配](references/runtime-codex.md) 或 [Claude Code 适配](references/runtime-claude-code.md)。单 Agent 不加载运行时适配。

## 1. 明确交付与关键未知

从输入和已有材料确定用户要得到的选择、方案、解释或文章论点，以及相关选项、约束和评价依据。只在概念歧义确实影响判断时澄清定义。

指出最可能改变结果的未知条件或取舍，据此组织分析。能从材料确定的内容自行处理；仅在无法验证的关键歧义阻碍工作时提问，其余给出明确假设并推进。

纯事实查询直接查证，简单比较直接回答，不为套流程拆分任务。对需要深入分析的任务，简短说明将检查什么及实际采用的执行方式。

## 2. 选择执行方式和任务分工

支持独立 Subagent 与单 Agent 两种方式：

- 用户明确要求真实或独立多 Agent：使用 Subagent；不可用则说明限制，不用单 Agent 冒充。
- 用户明确要求快速、简短或低成本：默认单 Agent 分析。若同时要求真实多 Agent，保留独立执行，缩小任务范围与复核次数。
- 其他适用任务：有可独立完成的比较或互补分析时默认使用 Subagent；任务无法有效拆分时由主 Agent 完成。
- 独立执行不可用且用户未禁止降级时，披露后用单 Agent 完成可做的部分。单 Agent 不声称实现了独立盲答或获得了多个独立结论。

先定义必要的分析任务，再决定 Agent 数量，通常 2–3 个足够；不为凑人数添加任务。主 Agent 负责整体判断、任务分配和最终交付，工作 Agent 只完成分配的分析或复核，结果经主 Agent 汇合。

区分两种分工：

**同题独立比较**：当独立判断有助于检查偏差时，给各分析者相同选项、基础材料与约束。第一阶段不共享答案、主 Agent 的预期结论或带结论的摘要；分批执行也保持隔离。

**互补分析**：当问题可拆分时，分别研究不同部分，共享必要背景并明确各自范围，无需重复回答同一道题。有依赖的任务顺序执行，不把依赖任务伪装成独立判断。

可以采用不同分析视角，但无需人物姓名、人格设定或独特口吻。用户指定思想家时，将其有来源依据的思想作为分析方法，明确是转述或模拟应用，不冒充本人观点，不虚构引语。

## 3. 收集结果并识别问题

按分析协议收集判断、依据、关键未知与适用条件，不预设各方必须一致或反对。主 Agent 检查：

- 判断差异来自材料、事实解释、价值偏好，还是不同假设？
- 是否有具体反例、遗漏约束或证据缺口足以改变结果？
- 一致判断是否依赖同一个尚未验证的前提？

这些是判断方向，无需逐项打分或输出检查表。只引用实际返回的结果；失败时按运行时说明处理，不代写独立分析。缺失部分会影响结论时在交付中说明。

## 4. 必要时交叉检查或查证

仅对会改变结果的问题继续工作。将需检查的具体判断及其依据原文、相关材料和复核问题交给合适的分析者；只有条目较多易混淆时才加编号。

复核可以检验反例、比较假设、补充证据或修正解释，不要求反驳。重要变化记录原判断、改变依据与新判断，不保留无关的重复表述。

缺失的是事实时，按宿主规则和可用工具查证；不能以继续交换观点代替证据。功能视角对读者或客户的推测不能写成访谈或市场反馈。

按结果收束：

- 主要判断已有足够支持，剩余分歧不影响行动：交付。
- 缺少决定性事实：查证；无法查证时给条件性判断及缺口。
- 具体矛盾或反例可能改变建议：做一次针对性复核，返回后重新判断；只有出现新的实质问题才继续。

不设固定轮数，不强求开放问题，也不因仍有未知就无限延长。默认自动完成任务；用户要求阶段参与时，在有实际选择需要用户判断的节点等待。用户要求停止时，基于已有结果交付。

## 5. 形成任务成果

正文直接给结果和依据，不逐个展示 Agent 的发言。用户需要详细过程时提供可公开的分析摘要、依据和重要修正，不输出内部调度信息或隐藏推理。

**决策任务**：说明建议、关键依据、相对主要备选项的取舍、会改变推荐的条件及下一步。依据不足时给条件性推荐，不硬选赢家。

**探索任务**：给出当前解释、支持与反对证据、实际存在的分歧，以及最有价值的后续问题；写作任务进一步提炼可用论点，不强凑唯一结论。

重要判断区分已核验事实、用户提供材料、推断和价值选择。多数同意不等于事实成立，分歧也不自动降低事实可信度；不用票数或机械评分生成置信度。

按内容自然组织，不要求固定标题、行动标签或逐段摘要。图表仅在能更清楚表达比较、关系或因果时使用。建议的下一步应服务于决定，已有充分依据时不附加形式化验证。

## 6. 按需保存

用户要求报告、需要后续复用或任务较复杂时，保存简洁分析记录；简单比较直接回答。用户明确要求不保存时遵从。

记录保留任务、必要材料与来源、关键判断、重要修正、结论及未解决条件，不逐字保存所有中间输出。需要保存时随重要进展记录依据和修正，避免结尾凭记忆重建。主 Agent 统一写入最终成果。

优先使用用户指定路径或项目现有报告目录，否则用当前目录的 `analysis-notes/`，文件名可为：

```text
YYYYMMDDTHHMMSS--{议题关键词}--analysis.md
```

用宿主时钟与文件能力确定时间和路径。交付时报告实际保存位置；无法保存则说明并提供可复制正文。明确本次是否使用独立 Agent，不把未运行的分析写成已完成。
