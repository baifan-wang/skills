# 可选分析视角

只选择能改变本次判断的视角；一个任务可以使用多个视角，也可以完全不使用本文件。视角不等于 Agent，不需要全部分配或形成固定阵容。

| 视角 | 有用的问题 |
|---|---|
| 证据与解释 | 材料支持到哪一步？还有什么合理解释？ |
| 假设与反例 | 哪个前提失效会推翻判断？是否存在具体反例？ |
| 约束与实施 | 现有资源下能否完成？关键依赖是什么？ |
| 简化 | 更简单的办法能否达到同样目标？ |
| 长期影响 | 眼前收益会带来什么后续限制？ |
| 理解与使用 | 表达可能怎样被理解？已有用户材料显示了什么？ |
| 利益与价值 | 谁承担代价？各选项依赖什么价值偏好？ |
| 系统与反馈 | 局部改变会如何影响其他部分？ |
| 先例与情境 | 先例的适用条件是否与当前相同？ |
| 替代方案 | 是否有满足约束但结构不同的办法？ |

## 任务拆分示例

公众号命名可分别分析表达歧义、与文章样本的匹配、长期内容延展性。结果按实际影响综合，不能以模拟评价人数当作市场偏好。

技术方案可分别分析需求覆盖、实现约束和主要替代方案。当争议来自可测行为时，复现或测试比增加观点更有效。

解释性问题可先独立提出有材料支持的解释，再检查最能区分它们的证据。材料不足时保留多种解释，不强制选定。
